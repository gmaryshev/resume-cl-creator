RESUME & COVER LETTER GENERATION WORKFLOW

ENTRY CONDITION
- The user places or updates the job description at `Job_descriptions/jobdesc`
  and starts this workflow by saying `go wf.txt`.
- Treat `Job_descriptions/jobdesc` as the job description for this run unless
  the user explicitly names another path.

STEP 0: BUILD THE CONTEXT BUNDLE
- Run this command from the repository root before reading reference material:
  `python3 workflow/bundle_context.py Job_descriptions/jobdesc`
- If the command fails, stop and report the error; do not generate documents or
  write application-tracking rows.
- Record the printed bundle directory path for this run.
- Read the generated `context.md` as the primary context package and
  `manifest.json` for source provenance, trust levels, and hashes.
- Use only sources included by `workflow/source_registry.json` as approved
  generation context. Do not silently add files from reference folders.
- The bundle contains the complete job description. Do not reread
  `Job_descriptions/jobdesc` separately unless verifying a source detail.
- For each item in `manifest.json` under `summarization.requests`, use the
  Copilot model to create a concise, source-traceable summary before drafting.
  Summaries must contain only facts supported by the named source. Preserve the
  original source path and section/location references. Never invent dates,
  metrics, technologies, responsibilities, or credentials.
- Keep the generated bundle directory under `.workflow/bundles/`; it is
  temporary run context and must not be copied into `Output/`.

STEP 1: ANALYZE THE JOB AND GATHER APPROVED CONTENT
- Use the job-description section of `context.md` to extract requirements,
  skills, responsibilities, location, employment type, company, job title, and
  URL if present.
- Use the personal-facts and reference-resumes sections of `context.md` for
  actual experience, skills, education, projects, and contact details.
- Treat `primary-fact` sources as factual evidence and
  `curated-example` sources as style/content references, not additional facts.
- Resolve conflicts according to source trust and the explicit rules in the
  bundled workflow-instructions sources. If a material conflict remains,
  surface it rather than guessing.

STEP 2: ANALYZE LATEX TEMPLATE STRUCTURE
- Use the latex-template section of `context.md` for styling inspiration and
  structural commands.
- Focus on document structure, formatting, and layout commands.
- CRITICAL: DO NOT copy any personal information from templates (names, emails,
  phone numbers, etc.). Use personal facts from approved sources instead.

STEP 3: SAVE JOB DESCRIPTION
- Save the complete job description as a PDF file in the run's Output/ folder
- Use the naming convention: (Job_Title_at_Company).pdf
- Preserve the job description text accurately; include the source URL and retrieval date when available
- Reuse an existing matching PDF file in the output folder when the job description has already been saved

STEP 4: CREATE OUTPUT FOLDER
- Create a new folder in Output/ with naming convention:
  (Job_Title_at_Company)_resume_cl_(llm_model)_(version_number)
  Example: Software_Engineer_at_Plexxis_resume_cl_Sonnet4.5_1
- Increment version_number (1, 2, 3...) for each new generation

STEP 5: GENERATE DOCUMENTS
- Create tailored resume and cover letter based on job description
- Use LaTeX format matching the template style
- Follow the writing rules and personal rules included in the context bundle.
- If a rule must be checked against its source, use the provenance path in
  `manifest.json`; do not broaden the source set without documenting why.
- Compile to PDF format

STEP 5A: CREATE INTERVIEW TIPS FILE
- Create a tips_Job_Title_at_Company.pdf file in the same folder as the resume and cover letter pdfs
- Content should include:
    - Your opinion of the job and how well my skills match it
    - Tips to prepare for the job interview

STEP 6: ORGANIZE OUTPUT FILES
- Place compiled PDFs ((full_name)_resume_(Job_Title_at_Company)_(version_number)_(llm_model_initials).pdf and (full_name)_cover_letter_(Job_Title_at_Company)_(version_number)_(llm_model_initials).pdf) in the main folder
  - LLM model initials: H for Haiku, S for Sonnet, Gr for Grok, etc.
- Place the tips_Job_Title_at_Company.pdf file in the main folder alongside the PDFs
- Create subfolder: (Job_Title_at_Company)_resume_cl_latex_(version_number)
- Store all LaTeX source files (.tex, .aux, etc.) in the latex subfolder

STEP 7: LOG JOB APPLICATION
- Only perform this step after all required PDFs compile successfully and the
  output structure is verified.
- Every completed run of this workflow is an application by default; do not wait for separate confirmation and do not ask for extra tracking information.
- At the end of every run, add one row to Job_tracking/applications.csv using a unique application_id.
- Record only facts produced by this workflow: application date, company, job title, job-description path, job URL if present, location/employment type if present, output folder, generated resume/cover-letter/tips files, LaTeX folder, LLM model, version, and status.
- Use repository-relative paths and leave unavailable fields blank; never guess missing facts.
- Set the initial status to "Applied" and status_date to the application date.
- Add one matching row to Job_tracking/status_history.csv with a unique event_id, from_status "Not Applied", and to_status "Applied".
- If a later status is explicitly provided, update applications.csv and append its transition to status_history.csv.
- Use the controlled status values documented in Job_tracking/README.md.
- Keep notes factual and concise; do not store passwords, account credentials, or other sensitive information.
- Verify that the application and status-history rows have matching application_id values.
